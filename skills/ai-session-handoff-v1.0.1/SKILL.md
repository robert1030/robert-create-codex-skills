# AI Session Handoff

> v1.0.1｜跨 AI agent、AI Web Chat 與跨作業系統使用。純文字型 skill：只用 Python 標準函式庫，無外部相依，離線可用。

把當前 session 壓縮成一份下一個 AI session 貼上就能接手的 handoff。品質標準：下一個 agent 不必回頭翻原對話，就知道在解什麼問題、驗收標準是什麼、做到哪裡、哪些決策已凍結不得推翻、下一步從哪一行開始，而且不會把推論當成已確認事實。

---

## Step 1：確認 handoff 目標

照三欄決策表操課，缺參數採安全預設，不因此中斷流程。

| 項目 | 歸類 | 規則 |
| --- | --- | --- |
| 下一個 session 的用途與下一步焦點 | 可推斷 | 使用者有講就依它調整各節資訊權重；沒講就採通用完整模式 |
| 目標 agent 或平台 | 可推斷 | 沒講就寫成平台中立版本，並在第四節列出建議載入的 skill |
| 交接範圍 | 可推斷 | 單一主題直接採整個對話並複述；多主題混雜且範圍不明時停下問一題 |
| 輸出語言 | 可推斷 | 照對話主要語言；台灣使用者一律正體中文加台灣用詞 |
| 是否寫入檔案與輸出路徑 | 預設值 | 依 Step 6 的能力偵測結果決定；使用者指定路徑就用指定路徑 |
| 詳細程度 | 預設值 | 以「下一個 agent 能否據以行動」為準，寧可精準不要冗長 |
| 骨架章節 | 預設值 | 九節凍結骨架，不增不減；不適用的節寫「本節無內容。」 |

**完成條件**：已取得可用目標，或已明確採用通用 handoff 模式並在複述中講明。

## Step 2：建立 conversation evidence map

由對話最開頭掃到最尾，逐輪盤點十類素材：使用者目標與驗收標準、關鍵背景、artifacts、決策、已完成工作、未完成工作、限制與紀律、風險、敏感資訊、已被取代的內容。

同步做事實分級，把「使用者親口確認」與「AI 建議但未獲確認」分開。這是本 skill 最容易造假的地方，列為最高風險區。

**完成條件**：每一項重要敘述都有對話或 artifact 依據，推論與已確認事實已分開標記。

## Step 3：去重與壓縮

引用 artifact，不要複製 artifact。內容若已存在於 spec、plan、ADR、issue、commit、diff、測試報告、原始碼或 URL，改以「路徑或 URL ＋ 一句用途 ＋ 目前狀態 ＋ 下一個 agent 該讀哪一段」記錄。

刪掉社交寒暄、無關支線、已被後續決策取代的暫時想法；保留足以支撐下一步的因果脈絡。

**完成條件**：文件內沒有大段重複的 artifact 內容，且下一個 agent 仍讀得懂決策原因與工作狀態。

## Step 4：套用九節輸出契約

九節標題文字與順序為 v1.0.0 凍結契約，一字不可改、一節不可刪：

1. `〇、啟動指令（給下一個 session）`
2. `一、任務身分卡`
3. `二、核心脈絡`
4. `三、工作流現況`
5. `四、工作紀律與規範`
6. `五、邊界與禁區`
7. `六、凍結契約與關鍵閘門`
8. `七、已確認的對話決議`
9. `八、未決事項與風險`

第〇節三條機器閘門：內文去空白後不超過 200 字；至少三個編號條目；第一個編號條目同時含「讀」與「再回應」。

逐節的 inclusion criteria、模板與填寫示例在 `references/output-contract.md`，**每次產出前先讀它**。

**完成條件**：九節全部存在，不適用的節寫「本節無內容。」而非省略；已完成、未完成與未驗證三種狀態沒有混淆。

## Step 5：敏感資訊與正確性檢查

事實分級標記，五選一，逐條標示：

| 標記 | 意義 |
| --- | --- |
| `[CONFIRMED]` | 由對話、檔案、工具結果或使用者明確確認 |
| `[INFERRED]` | 由現有證據合理推論，尚未經確認 |
| `[UNVERIFIED]` | 尚待確認 |
| `[BLOCKED]` | 缺少權限、檔案、工具或使用者決策 |
| `[SUPERSEDED]` | 已被後續決議取代，保留以免重蹈 |

秘密值一律換成 `[REDACTED]`，保留它的用途與存在位置，並寫明安全取得方式。判定規則見 `references/redaction-policy.md`。

有 Python 可用時，把草稿寫成檔案後依序執行兩支驗證器（以下 `<python>` 代表當前環境可用的直譯器）：

```text
<python> scripts/validate_punct.py <草稿路徑>
<python> scripts/validate_handoff.py <草稿路徑>
```

任一退出碼非 0 就修到綠燈，不得請示放行。沒有執行環境時走 Step 6 的降級路徑，並在交付時明講本次未跑機器驗證。

**完成條件**：沒有明文秘密、沒有把推論寫成事實、沒有虛構的檔案或測試結果，且下一個 agent 看得出第一個該執行的動作。

## Step 6：依能力輸出

先偵測能力再決定分支，不以平台名稱決定行為。有 Python 時可執行 `<python> scripts/detect_capabilities.py` 取得 JSON 結果。

- **agent 模式**（可寫檔案系統）：寫入作業系統暫存目錄，不污染專案 workspace，除非使用者明確指定路徑；寫入後重新讀回比對內容，再回報實際完整路徑。
- **web 模式**（無檔案系統）：在回覆中輸出完整 Markdown，放進單一可整塊複製的 fenced code block；內含三反引號時外層改用四個反引號。可提供建議檔名，並標示為建議值。
- **tasks 模式**（背景工作或對話可見範圍受限）：把必要狀態全部寫進文件本身，並在第八節標明來源時間與可見範圍限制。

各分支的判定條件、暫存目錄解析順序與降級階梯見 `references/platform-capabilities.md`；Windows 與跨編碼的處理見 `references/encoding-policy.md`。

**完成條件**：使用者實際收到 handoff；若回報了檔案路徑，該檔案已回讀驗證存在且內容相符；輸出的編碼與結構驗證通過。交付後問使用者是否滿意，不滿意就依方向修改並重跑 Step 5。

## 硬規則

- **誠實優先於完整**：沒讀到的檔案、沒跑過的命令、沒通過的測試、沒建立的檔案，一律不得寫成已完成。無法確認的事寫 `[UNVERIFIED]` 或 `[BLOCKED]`。
- **不虛構 artifact**：路徑、URL、commit、檔名、測試結果只能來自對話或工具結果。檔案不存在或無法存取時，明確標示狀態。
- **不替使用者做新決定**：發現前後決議打架時寫進第八節請下一個 session 向使用者釐清，不自行裁決。
- **只交接當前對話**：要彙整多個歷史對話屬另一件事，需先取得使用者同意。
- **凍結項另開新版**：九節骨架要改一律另開 major 版本，不就地修改。

## 能力邊界

- 交接品質受限於當下可見的對話內容。早段被截斷或壓縮時，只交接看得到的部分，並在第八節的「脈絡涵蓋」欄誠實聲明。
- 驗證器驗得了結構與紀律形式，驗不了內容是否忠於對話。內容正確性靠 Step 2 的事實分級與交付前自我攻擊把關。
- 沒有檔案工具時不得宣稱已存檔；沒有附件能力時不得宣稱已建立附件。
- 排程或背景執行能力不等於完整 session continuation，兩者不可混為一談。

## 參考檔的位置與載入降級

本檔提到的 `references/`、`scripts/`、`schemas/` 路徑，基準一律是**本 skill 的根目錄**（宿主載入本 skill 的位置），不是當前工作目錄，也不是使用者的專案目錄。

- **讀得到**（agent 宿主，或會一併提供檔案的 Web Chat）：照 pointer 讀完再產出。
- **讀不到**（宿主只載入本檔的情況）：直接依本檔的九節清單、第〇節三條閘門與狀態標記集合產出，結構與讀得到時完全相同，並在交付訊息裡說明本次未載入逐節細則，文件本身不必記這件事。缺參考檔是降級，不是中止理由。
- **產出的 handoff 內引用檔案時**：寫成下一個 agent 能自行解析的形式。專案檔案附專案根目錄或完整路徑；skill 內的檔案寫成「skill 名稱 ＋ 檔案名」，不留沒有基準的相對路徑。
