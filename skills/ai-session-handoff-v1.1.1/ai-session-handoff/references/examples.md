# 範例

## 最小可用交接文件

以下是通過全部驗證器的最短合格範例。它示範九節俱在、狀態標記逐條、artifact 以引用方式記錄、第八節帶「脈絡涵蓋」欄。實務上各節會更長，但不得比這更少。

```markdown
# Session 交接摘要｜交接驗證器上線｜2026-08-04

## 〇、啟動指令（給下一個 session）

你是接手本工作的新 session。請依序執行：①完整讀完本文件再回應；②載入第四節列出的紀律；③嚴守第六節凍結項，不重新決策；④從第一節的下一步接手並先複述理解。

## 一、任務身分卡

- 任務名稱：交接文件驗證器上線
- 任務目標：讓交接文件在交付前可被機器驗證
- 使用者期望：非 0 退出碼一律修到綠燈才交付
- 目前階段：驗證器已可執行，尚未接進封裝流程
- 主要交付物：`scripts/validate_handoff.py`
- 完成標準：五組 fixture 全綠且封裝掃描無殘留
- 下一步：把驗證器接進封裝腳本並補一組失敗案例
- 指定焦點：通用延續

## 二、核心脈絡

交接文件過去只靠人工檢查，漏節與空節反覆發生。九節骨架為凍結契約，驗證器負責結構與紀律形式，內容正確性仍由撰寫者負責。

## 三、工作流現況

- 已完成：結構驗證器 `scripts/validate_handoff.py`｜九節與紀律閘門｜本機實測退出碼 0 [CONFIRMED]
- 進行中：封裝腳本整合｜卡在測試資料尚未齊備 [CONFIRMED]
- 尚未開始：說明文件更新 [CONFIRMED]
- 被阻塞：雲端測試環境 `ci/pipeline.yaml`｜缺少執行權限 [BLOCKED]
- 已放棄：以正規表示式檢查語氣的做法｜誤判率過高 [SUPERSEDED]
- 需要驗證：Windows 主控台輸出是否會亂碼 [UNVERIFIED]

## 四、工作紀律與規範

- 語言：正體中文，台灣用詞。
- 標點：全形標點，不使用破折號。
- 編碼：UTF-8 without BOM ＋ LF。
- 品管：交付前跑標點與結構兩支驗證器，非 0 不交付。
- 建議載入的能力：本 skill 的輸出契約參考檔，以及使用者既有的作業紀律規範。

## 五、邊界與禁區

- 檔案一律寫入作業系統暫存目錄，需要進專案時先取得使用者同意。
- 憑證只記錄用途與取得方式，值以 [REDACTED] 表示。
- 凍結章節結構要改時另開 major 版本，不就地修改。

## 六、凍結契約與關鍵閘門

- 九節骨架標題與順序（2026-08-04 定版）｜改動一律另開 major 版本 [CONFIRMED]
- 交付前必須通過標點與結構兩支驗證器 [CONFIRMED]
- 動工前先複述理解，取得確認才改動凍結區以外的內容 [CONFIRMED]

## 七、已確認的對話決議

- 驗證器以退出碼作為唯一閘門｜原因：肉眼檢查漏過三次｜影響：所有交付路徑｜可重新討論：否｜來源：使用者明講 [CONFIRMED]
- 狀態標記採 ASCII 方括號｜原因：中文標籤不易穩定比對｜影響：模板與驗證器｜可重新討論：是｜來源：AI 建議，使用者未反對 [INFERRED]
- 先前打算用語氣分析判斷祈使句｜已被誤判率證據推翻 [SUPERSEDED]

## 八、未決事項與風險

- 待使用者決定：是否把驗證器接進提交前掛鉤 [UNVERIFIED]
- 待外部查證：雲端環境的權限申請流程 [BLOCKED]
- 技術風險：Windows CP950 主控台輸出可能出現跳脫字元，不影響退出碼 [INFERRED]
- 平台差異：WSL2 與 Windows 原生路徑格式不同，範例需兩種都給 [CONFIRMED]
- 脈絡涵蓋：本對話全程可見，來源時間 2026-08-04。
```

## 五組完整情境範例

`tests/fixtures/` 內有五組情境的完整素材，每組包含輸入對話 `conversation.md`、預期事實 `expectations.json` 與通過驗證的交接文件 `handoff.md`：

| 情境 | 目錄 | 重點 |
| --- | --- | --- |
| 技術開發工作 | `tests/fixtures/dev/` | 多檔案 artifact、測試結果、凍結契約 |
| 長篇研究工作 | `tests/fixtures/research/` | 來源引用、未查證事項、推論與事實分離 |
| 文件撰寫工作 | `tests/fixtures/writing/` | 風格紀律、版本、審稿意見 |
| 跨平台疑難排解 | `tests/fixtures/troubleshooting/` | 平台差異、編碼問題、降級路徑 |
| 敏感資訊與多 artifact | `tests/fixtures/sensitive/` | 遮蔽、憑證取得方式、被阻塞事項 |

`tests/test_golden.py` 會對每一組檢查：必要事實是否出現、禁止內容是否確實不存在、下一步是否可執行、artifact 引用是否帶狀態、遮蔽是否完成。
