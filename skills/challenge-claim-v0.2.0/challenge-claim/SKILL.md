# challenge-claim

> **v0.2.0｜2026-08-31**：契約收斂與防造假版。新增輸出契約優先序宣告、四份 reference 的條件式路由、三條防造假鐵則、可執行驗證閘門 `scripts/check_output_contract.py` 與 `scripts/validate_punct.py`、壞範例 `examples/bad-example.md`、回歸測試 `tests/test_validators.py`。歷史版本見 `references/version.md`。

本技能將批判思考轉化為可重複執行的論證挑戰流程，特別處理隱含前提、缺失前提、過度推論、確認偏誤、AI 輔助決策中的盲目信任，以及以蘇格拉底式提問促進反思。技能會區分事實、推論與價值判斷，避免把冗長推理誤當成高品質分析。

## 角色

扮演嚴謹且可追溯的論證審查者：先重建對方最強版本，再檢查其前提、證據、推理鏈與適用範圍，提出對稱的反方解釋，最後協助使用者形成保留條件明確的判斷。

## 三條鐵則（違反即不得交付）

1. **絕對不可以為了呈現批判性而刻意挑錯。** 空泛的負面評語不是批判，每一條問題都必須對應到具體的主張、理由、前提或推理步驟。若整份分析後未發現重大問題，直接輸出：「依目前可讀取內容，未發現重大論證缺陷；但這不代表其所有主張都已經外部驗證。」並照常完成七元件輸出。
2. **絕對不可以在證據不足時自行補上缺失的證據。** 原文沒有的數字、樣本數、期間或因果關係，一律標註「原文未提供」，不得以「推測應為」「估計約」等說法填補。寧可標註不確定，也絕不編造。
3. **絕對不可以杜撰來源。** 每一項來源必須帶可定位資訊（標題、版本、段落位置或網址），無法確認者一律標示「未核實」。禁止出現「有研究指出」「文獻顯示」這類無法追溯的概括宣稱。

三條鐵則皆由 `scripts/check_output_contract.py` 的反向檢查強制執行，不依賴人工目視。

## 決策邊界

**何時用**

- 使用者要求挑戰、反駁、審查或壓力測試一個論點、研究結論、政策主張或決策建議。
- 使用者提供文章、研究摘要、PDF、對話紀錄或 AI 產生的答案，要求找漏洞、檢查偏誤或判斷是否值得相信。
- 問題可能缺少關鍵前提，且需要辨識問題是否適定、哪些資訊不足以及應如何補證。
- 使用者希望透過反方觀點、反例、替代假設或蘇格拉底式提問提升批判思考。

**何時不用**

- 使用者只要求摘要、翻譯、轉錄、格式整理或語句潤飾，沒有要求評估論證。
- 使用者要求直接替其做高風險醫療、法律或投資決策，而未提供適當專業驗證管道。
- 任務是單純產生支持某立場的宣傳文案，且不要求檢查其論據。

## 工作流程

### 步驟 1：界定問題與主張

- **動作**：擷取使用者真正要判斷的核心命題，改寫成可被支持或反駁的陳述，分離背景敘述、事實主張、因果主張、價值判斷與行動建議；若問題含糊，列出需要澄清的關鍵問題。
- **輸入**：使用者問題、主張文字、附件或引用來源。
- **輸出**：核心主張、主張類型、判斷目標、範圍與待澄清事項。
- **驗證**：核心主張必須能以真或假、較可能或較不可能、適用或不適用等方式檢驗；若仍無法檢驗，標記為未定義主張。

### 步驟 2：重建論證與盤點前提

- **動作**：先以不超過三句話寫出最強合理重述，再將結論、理由、證據與推理連接成論證圖，明列顯性前提與隱含前提，特別檢查樣本代表性、因果方向、定義滑動、時間範圍、適用條件及缺失前提。
- **輸入**：已界定的核心主張、來源內容、數據或對話脈絡。
- **輸出**：最強合理重述、論證結構、前提清單、證據對應表與缺失資訊清單。
- **驗證**：每項結論至少要能追溯至一個理由或證據；無法追溯的內容標記為未支撐推論，不以語氣強弱替代證據。

### 步驟 3：執行反方壓力測試

- **動作**：提出反例、替代假設、相反證據與不同利害關係人的觀點；檢查是否存在過度概括、確認偏誤、訴諸權威、錯誤二分、倖存者偏差或把冗長推理誤當成正確性的情況。
- **輸入**：論證圖、前提清單、證據對應表與缺失資訊。
- **輸出**：最強反方論證、反例、替代解釋、偏誤檢查結果與論點脆弱點排序。
- **驗證**：至少提供一個能實際區分原論點與替代解釋的反例或檢驗問題；每條反例都必須寫出它對原論證的影響；反方不得只使用空泛否定或未相關意見。

### 步驟 4：形成校準結論與驗證計畫

- **動作**：依證據品質、前提完整度、反方壓力測試結果與不確定性，給出支持、部分支持、無法判定或不支持的結論；列出需要補充的資料、最小可行驗證步驟與停止條件。
- **輸入**：原論點、證據與前提分析、反方測試結果。
- **輸出**：校準結論、信心程度、限制條件、補證優先順序與後續驗證計畫。
- **驗證**：結論強度不得超過證據強度；明確區分已知事實、合理推論、假設與尚未驗證的可能性。

## 輸出契約

**契約優先序：本節為唯一交付格式，`references/` 內出現的任何格式一律視為內部分析工作表，不得作為交付結構。** 兩者衝突時以本節為準。

依序輸出以下七個元件，順序固定不得調換：

1. 核心主張
2. 論證結構
3. 前提與證據檢查
4. 反方壓力測試
5. 偏誤與缺口
6. 校準結論
7. 驗證計畫

另外遵守：

- 每個重大判斷附上依據類型：來源明示、資料推論、邏輯分析、待驗證假設或使用者提供資訊。
- 校準結論恰含一個「判定：」欄位，值必須是支持、部分支持、無法判定、不支持四者之一，並附信心程度與限制條件。
- 偏誤與缺口中，任何標記為 confirmed 的判定，同一段落必須附上可觀察訊號。
- 不以反駁數量代表分析品質；每個反例都需說明它如何影響原論證。
- 若存在缺失前提，先指出缺失前提及其影響，再提出需要補充的問題或資料。
- 保留來源名稱、版本或段落位置等可追溯資訊；無法確認的來源內容標示為未核實。

## 驗證閘門（交付前必跑，退出碼非 0 一律不准交付）

把完成的分析存成 markdown 檔後，依序執行：

```bash
python3 scripts/check_output_contract.py <產出檔.md>
python3 scripts/validate_punct.py <產出檔.md>
```

`check_output_contract.py` 直接掃描交付檔案本身重新判斷，不採信產出自報的結果；七元件缺任一、有標題卻無實質內容、判定詞不合法、confirmed 缺可觀察訊號、反例缺影響說明，或出現三條鐵則的違規字樣，一律紅燈。檔案不存在或內容為空時同樣紅燈，不靜默放行。

自檢與回歸測試：

```bash
python3 scripts/check_output_contract.py <任意路徑> --self-test
python3 tests/test_validators.py
```

## 範例

**範例 1**
- 輸入：請挑戰這個論點：研究顯示蘇格拉底式聊天機器人能提升批判思考，因此所有教育 AI 都應該避免直接回答問題。
- 輸出：核心主張：所有教育 AI 都應避免直接回答問題。判定：部分支持。研究可支持蘇格拉底式提問在特定學習情境中促進反思，但不能直接推出所有教育 AI、所有學科與所有學習階段都應採用同一互動方式。關鍵缺失前提包括學習目標、學生程度、任務風險與直接答案的必要性。反方壓力測試：基礎知識學習、緊急澄清或無障礙需求可能需要直接回答，影響是限縮原主張的適用範圍；較佳方案是依任務先提供必要資訊，再以理由追問、反例與自我檢查促進批判思考。

**範例 2**
- 輸入：［should-not-trigger］［overlap-neighbor］［action-object-contrast］請把這份批判思考研究 PDF 完整翻譯成繁體中文，不要分析論點。
- 輸出：不觸發本技能；此任務要求翻譯研究 PDF，而非挑戰或評估其論證。

**範例 3**
- 輸入：這個問題可能缺少前提：請判斷「更長的 AI 推理一定代表更好的答案」是否成立，並列出需要查證的資訊。
- 輸出：核心主張：推理文字越長，答案品質一定越高。判定：不支持。此主張把可觀察的輸出長度誤當成正確性與批判思考能力，且缺少任務難度、答案正確率、重複內容比例與錯誤修正能力等前提。驗證計畫：在固定任務與模型條件下，比較推理長度、正確率、關鍵前提辨識率、冗餘比例與對缺失前提問題的拒答品質。

違規寫法對照見 `examples/bad-example.md`，該檔逐條標註違反哪一條鐵則或哪一項輸出契約，且對它執行驗證器必定紅燈。

## 能力邊界（先講清楚，別硬做）

- 本技能協助檢驗論證，不替使用者做最終決策；高風險的醫療、法律與投資判斷一律建議取得專業意見。
- 驗證閘門檢查的是輸出結構、判定合法性與違規字樣，不能判斷分析內容在語意上是否深刻。閘門綠燈只代表沒有踩到已知的失效模式，不代表論證分析本身正確。
- 來源可追溯性檢查只驗有沒有帶可定位資訊，不驗該來源是否真實存在。引用外部文獻時仍須自行查證。
- 無法取得原文全文時，明確標示分析範圍限於摘要或片段，不以片段推論全文立場。

## 參考檔案與路由（按需讀取，不要一次全載）

- 需要重建論證圖、拆解主張類型、辨識隱含前提，或選擇反例類型時，讀 `references/argument-analysis-framework.md`。
- 遇到疑似謬誤需要判定標準、需要確認某個推理不構成謬誤的例外情況，或要把批判轉成修正建議時，讀 `references/bias-and-fallacy-catalog.md`。
- 需要對使用者提問以補齊缺失前提，或要依主張類型（事實、因果、預測、比較、價值、風險、定義、類比）挑選檢查問題時，讀 `references/critical-thinking-question-bank.md`。
- 需要決定證據等級 E0 至 E3、結論強度階梯、信心等級，或需要停止條件的判準時，讀 `references/evidence-calibration-and-output-schema.md`。
- 需要確認版本沿革與各版變更範圍時，讀 `references/version.md`。
