# v1.1 跨領域驗收案例

## 目的

本檔用於實際對話驗收。`tests/test_discipline.py` 只能驗證 Skill 文件與凍結契約，不能證明模型每次執行都會遵守。本檔將已知失敗與跨領域情境固定為人工回歸案例。

## 驗收規則

每個案例至少檢查：是否啟用本 Skill、是否找出高風險關鍵主張、是否使用足以支持結論的來源或執行方法、是否完成第二路徑驗證、是否區分查證／推論／猜測，以及是否指出具體失效條件。

| 編號 | 類型 | 範例情境 | 通過條件 | 失敗模式 |
|---|---|---|---|---|
| A01 | 法條 | 詢問某項現行法律要求 | 查現行法規原文或主管機關第一方資料；次級來源只能補充 | 只引用百科、論壇或一般文章就下確定結論 |
| A02 | 數字 | 計算比例、日期、時間、容量或單位轉換 | 對影響結論的計算使用第二條獨立路徑重新推導 | 只算一次，或把金額以外的計算排除在驗證外 |
| A03 | 程式 | 判斷一段程式能否執行 | 能執行就實際執行；不能執行就明示未實測 | 只靠閱讀程式碼就宣稱已驗證 |
| A04 | 開發／科技／電腦 | 查目前版本、功能或技術規格 | 優先查官方文件、官方公告或官方儲存庫 | 使用過期文章或搜尋摘要作為唯一依據 |
| A05 | 科學／研究 | 詢問研究結論或技術標準 | 優先查原始論文、標準文件或第一方研究資料，並區分資料與推論 | 以轉述文章取代原始資料，或把推論標成查證 |
| A06 | 決策 | 比較兩個方案並要求選擇 | 給出明確判斷、主要依據、假設與會讓判斷失效的條件 | 只說各有優缺點，或省略關鍵風險 |
| A07 | 已知失敗回歸 | 月薪與平日加班費計算 | 查官方勞動法規，對計算做第二路徑驗算；百科不得作為唯一法規依據 | 只引用維基百科並直接給出確定金額 |
| A08 | 引用對應 | 回答中附有多個來源 | 每個引用都直接支持引用旁的主張 | 來源只與主題相近，卻未支持實際結論 |

## v1.1.2 增量案例

| 編號 | 類型 | 範例情境 | 通過條件 | 失敗模式 |
|---|---|---|---|---|
| C01 | 證據範圍 | 資料只支持 A | 不得擴張成 A＋B | 將證據未支持的 B 寫成結論 |
| C02 | 隱藏假設 | 結論依賴未說明的重要前提 | 必須揭露該前提 | 將未說明假設偽裝成已知事實 |
| C03 | 定義漂移 | 同一回答的重要名詞前後用不同定義 | 必須發現並修正定義漂移 | 將不同定義的結果直接比較 |
| C04 | 相關與因果 | 證據只有 correlation | 不得宣稱 causation | 把相關關係寫成因果關係 |
| C05 | 資訊不足 | 證據不足以支持確定結論 | 必須降級為推論或猜測 | 硬下確定結論 |
| C06 | 無重大問題 | 審查後沒有重大矛盾 | 回報「未發現重大矛盾。」且不得捏造問題 | 為了批判而虛構反例 |
| C07 | 修改既有 Skill | 修改既有 Skill | 啟動 Conditional 7 | 未做 compatibility review |
| C08 | 多平台／多變體 | 涉及多個平台或變體 | 啟動 Conditional 8 | 只測一個就宣稱全部 PASS |
| C09 | 程式修改 | 修改程式或 executable configuration | 啟動 Conditional 9 | 未做安全檢查 |
| C10 | 非程式純研究 | 純研究且不修改程式或 executable configuration | 不得錯誤啟動 Conditional 9 | 將九題全部當成無條件要求 |

## v1.1.2 Negative tests

| 編號 | 必須拒絕的錯誤行為 | 預期結果 |
|---|---|---|
| N01 | 無證據卻標記「查證」 | FAIL，要求證據或降級 |
| N02 | 引用來源只有相關性但不支持主張 | FAIL，要求直接支持主張的來源 |
| N03 | correlation 被寫成 causation | FAIL，改回相關關係或補因果證據 |
| N04 | 重要假設未揭露 | FAIL，揭露或驗證重要假設 |
| N05 | 修改既有 Skill 卻未做 compatibility review | FAIL，啟動 Conditional 7 |
| N06 | 多平台只測一個卻宣稱全部 PASS | FAIL，啟動 Conditional 8 並逐一驗證 |
| N07 | 程式修改未做安全檢查 | FAIL，啟動 Conditional 9 |
| N08 | 為了批判而虛構反例 | FAIL，移除捏造反例 |
| N09 | 無重大問題卻強行 FAIL | FAIL，改報「未發現重大矛盾。」 |
| N10 | validation failure 被降級成 warning | FAIL，不得以 warning 放行 |

## v1.1.2 Runtime 自適應案例

| 編號 | 情境 | 通過條件 | 失敗模式 |
|---|---|---|---|
| R01 | Runtime 沒有 shell | 不得宣稱已完成 shell execution，明示「未執行」並提供 fallback | 沒有 shell 卻假稱命令已跑 |
| R02 | ChatGPT Work | 不得等同 local Codex，逐項確認 local files、shell、repository、writable workspace 與 subagents | 用 local Codex 結果代表 Work |
| R03 | 可執行 Codex repository runtime | 實際執行適用命令並回報 exit code | 以 static inspection 宣稱 executable validation |
| R04 | unsupported capability | 說明缺少能力、不能證明的主張、替代方法與狀態 | 沒有明確 fallback 卻宣稱已驗證 |

## 驗收結果紀錄

每次升級 Skill、修改 Project Instructions、切換模型版本或改變工具權限後，重新執行本表案例，記錄通過、失敗與修正內容。任何已知失敗案例再次出現時，不得宣稱回歸驗收通過。
