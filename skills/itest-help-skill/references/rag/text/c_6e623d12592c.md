# Capturing Manual (Interactive) Sessions > Overview: Creating a test case by capturing interactive sessions > Overview: Capture view

iTest records every step in any interactive session that you start. The Capture view lists every session and step that iTest has captured. iTest also provides you with an option to view sessions and steps captured during an interactive session on a remote Velocity Core VM, when connected.

![](images/capture_local_remote.png) <!-- image_ref -->

![*](bullet_blue_rectangle.jpg) <!-- image_ref -->

- Local: Displays all the steps in any interactive session that you started. You can add comments and markers to the captured steps in iTest.

![*](bullet_blue_rectangle.jpg) <!-- image_ref -->

- Remote: Displays all the steps in any Interactive Workflow Automation (IWA) session started on Velocity Core, when connected.

> **Note：** Note If you have set up Velocity Core login information in Preferences > Spirent > Velocity (Configure Velocity preferences), then iTest connects to Velocity Core and displays call steps captured in the interactive sessions.

When not connected to a remote machine, iTest displays: Not connected. Please click here to connect.

Click the link and the Login to Velocity Core window displays. Enter the Velocity Core Server URL, User Name, and password, click OK (the window closes). Continue to work with Capture View.

The Capture view will be refreshed automatically and the message Fetching resources... displays.

You can use the information in the Capture view for a variety of purposes:

![*](bullet_blue_rectangle.jpg) <!-- image_ref -->

- You can select items to create a capture report that documents what has happened.

![*](bullet_blue_rectangle.jpg) <!-- image_ref -->

- You can drop captured steps into an existing interactive session to replay the steps.

![*](bullet_blue_rectangle.jpg) <!-- image_ref -->

- You can use selected steps or whole sessions to generate a new automated test case or add the steps to an existing test case.

See Working in the Capture view.

> **Important：** Important For CLI sessions, iTest also captures the unique text of the prompts returned by the session. As you can imagine, the ability to distinguish between a prompt and an extended wait for a response is very important during automated execution. iTest does much of the work of learning prompts behind the scenes, and we’ll discuss how you can help to train iTest to recognize prompts.
