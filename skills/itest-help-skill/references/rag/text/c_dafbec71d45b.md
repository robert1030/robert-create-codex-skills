| iTest command | Description |
| cd | With no argument, cd returns the current directory. With a directory as the argument, changes the directory that will be used as the working directory when processes are started or run. This does not affect the working directory of current processes. cd cd directoryPath |
| kill ?processID? | A kill step is complete immediately. The response to a kill command contains a message indicating whether the process was killed or was already complete. |
| run | Starts a new process and waits for it to complete. iTest does not move to the next test case step until the process is complete. You have the option to use a Timeout Completion rule to limit run time. The application window appears on the screen unless you set the Create No Window property to True. In most cases (for example, GUI applications), set Create No Window to False (the default setting). Optional: Use the -q[uiet] argument before the command to display only command output in the response, and not the exit code text, typically: Process 1 terminate, exit code: 0 Response run accepts all STDOUT produced by a process. Windows applications might not display the same STDOUT in the window. All process STDOUT is returned in the response body. Any STDERR is appended to the response body with a leading STDERR: string. There are two response headers: Result and ExitTime. Result returns the integer code that the associated process specified when it terminated. ExitTime returns the time that the associated process exited. Arguments run applicationName applicationName is the file to be executed (which can be an executable or a file that the operating system can start because of a file association) and may optionally contain additional arguments. If the filename includes spaces, then it must be surrounded by double-quotes. (The arguments should not be surrounded by quotes.) The result and the output of the process are placed into the response for the run step. |
| show platform | Returns information about the operating system in the body of the response. Here's an example: Process>show platform name: Windows XP ver: 5.1 arch: x86 type: win32 The intended use of the show platform action is to determine the operating system of the local computer (Windows or Linux). Based on the result, you can decide whether to send backslash \ or forward slash / characters in subsequent commands. |
| show process | show process processID Returns process status information (running or terminated, exit code if terminated). show process Returns process status information for all processes started in the current session (running or terminated, exit code if terminated). |
| start | Starts a new process on the local computer. The test case step is complete immediately after starting the process. Typically, test case execution immediately moves to the next step. A process started with start that has not ended by the time test case execution completes is automatically killed. Arguments start applicationName The command cell for a start action contains the file to be executed (which can be an executable or a file that the OS can start because of a file association) and may optionally contain additional arguments. If the filename includes spaces, then it must be surrounded by double-quotes. (The arguments should not be surrounded by quotes.) Concurrent Sessions The device name and session fields for the start step (if any) associate this process instance with other Process actions that execute later in the test case. This enables you to start several processes that will run concurrently. Portability To make test cases portable, define a parameter that holds the filename of the file to be executed. The command can use a field replacement to populate the filename. |
| wait | Blocks the session window until the specified process terminates (by external action for example). wait processID |
