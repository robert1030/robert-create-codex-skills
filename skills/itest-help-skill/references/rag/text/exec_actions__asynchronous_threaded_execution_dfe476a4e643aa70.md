# iTest EXEC actions, grouped by function > iTest EXEC actions, grouped by function > Asynchronous (threaded) execution

The following actions are described in “Making your test case thread-safe”:

lock: Ensure one thread for a specified block of code See page 1022 in Chapter 34.

signalWait: Sleep the currently executing thread See page 1023 in Chapter 34.

signalWaitAll: Wait until all specified events have been signaled or activated See page 1024 in Chapter 34.

signal: Wake a thread that is waiting on an event See page 1025 in Chapter 34.

signalAll: Wake all threads that are waiting on an event See page 1026 in Chapter 34.

signalActivate: Turn a signal on See page 1027 in Chapter 34.

signalClear: Deactivate a signal See page 1028 in Chapter 34.

waitThread: Wait for steps to complete See page 1028 in Chapter 34.

Also, see the related action: The ‘dumpState’ action: Return Threads view content, Data view content, and a summary of execution results
